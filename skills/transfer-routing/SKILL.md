# 掌银转账意图识别与要素提取

用于分析用户对话中的转账意图，并提取转账所需的各个要素。

第一阶段：判定是否为转账意图（支持人民币、非预约转账）  
第二阶段：提取转账要素（付款卡、收款人、银行、金额等）  
第三阶段：Router 调用子工作流进行转账

当用户进行转账相关的对话时，必须使用此技能来识别意图和提取关键信息。

## 概述

该技能用于在掌银对话场景中，完成以下三个阶段的任务：

- **第一阶段**：转账意图与支持范围判定
- **第二阶段**：转账意图信息抽取
- **第三阶段**：由 Router 在执行模式下调用子工作流进行转账

---

## 第一阶段：转账意图与支持范围判定

根据【当前用户输入】判断：

1. 是否为“转账/打款”意图
2. 是否为本智能体支持的转账类型（人民币、非预约、农行卡转出）

### 判定步骤（必须按顺序执行）

让我们一步一步分析问题。

#### Step1：是否转账意图

满足任一即视为转账意图（哪怕要素不全）：

- 直接发起：转账、转钱、打钱、打款、转给 X、给 X 转、给 X 打款、往 X 账户转、向 X 银行卡转、我想转 XXX 元、我要转、给我转、手机号转账
- 询问如何转账：怎么转账、如何转账、转账到 X 怎么操作
- 补充转账要素：转 XX 元、收款人是 X、用 XX 卡转、从 XX 银行转出、尾号 XX 转出、收款人姓名……
- 选择转账卡片：第 X 张卡、用第 X 张卡、用 X 张卡转

以下不算转账意图：

- 查询类：查余额、查流水、查明细、查转账记录、查到账没
- 其他业务：汇款、开卡、挂失、改密码、贷款、理财购买、信用卡还款（若用户明确是“还信用卡/还款”）
- 闲聊 / 与转账无关的话题（比如用户问“你好”）

**若不是转账意图：**

结果为：**不是转账意图**

**若是转账意图，执行 Step2**

#### Step2：是否为不支持的币种 / 预约

> 常见的金额单位（十、百、千、万、亿、兆）不是币种，识别到则跳过 Step2

若用户明确为外币 / 跨币种（如美元、USDT、欧元、外汇、换汇后转等）：

结果为：  
**不支持的转账意图，但是目前仅支持人民币业务，请查找外汇功能**

若用户明确为预约 / 定时 / 延时转账（如“2 小时后转 / 明天转 / 定时转 / 预约转账 / 到点自动转”）：

结果为：  
**不支持的转账意图，仅支持实时人民币转账，预约转账请使用预约功能**

#### Step3：转出卡银行是否为农行（仅在转账意图成立后执行）

- 转出卡银行仅以用户原文明确出现为准（如“用工行卡转 / 从招商银行转出 / 走中信”）
- 若用户未提及转出卡银行：**默认视为农行卡转出**
- 若用户提及转入卡银行（如“给我的招行卡转 / 转给建行卡”）：继续
- 若用户明确提及转出卡银行，且可判断为 **非中国农业银行 / 农行 / ABC**（如“用我的招行卡转”“从我的招行卡转”）

结果为：  
**不支持的转账意图，非农行卡转出**

- 若用户明确提及为农行：则继续

#### Step4：支持

若通过 Step1 ~ Step3：

结果为：**明确的转账意图**

### 第一阶段结果

可能返回以下之一：

- 这是明确的转账意图，执行第二阶段
- 这是不支持的转账意图，但是目前仅支持人民币业务，请查找外汇功能
- 不支持的转账意图，仅支持实时人民币转账，预约转账请使用预约功能
- 不支持的转账意图，非农行卡转出

## 第二阶段：转账意图信息抽取

**前提**：第一阶段判定结果为明确的转账意图

基于【当前用户输入】抽取本次转账要素信息，**不得使用常识进行补全**，不得猜测、不得改写用户意思。

### 需要抽取的要素（允许为空字段）

- 付款卡卡号/尾号
- 付款卡备注（如：理财卡、工资卡等）
- 收款人姓名
- 收款卡银行
- 收款卡卡号/尾号
- 收款手机号/尾号
- 收款卡备注（如：儿子、妈妈、老婆、同事、工资卡、理财卡、租房等）
- 转账金额
- 是否手机号转账

### 抽取规则（强约束）

让我们一步一步分析问题。

#### 1. 只抽取用户问题中明确出现的信息

未明确提及则输出空字符串。

#### 2. 卡号 / 尾号字段的定义

只要【用户当前输入】出现“卡号 / 账号 / 银行卡号 / 尾号 / 末 X 位 / 后 X 位 / 尾数 / 最后 X 位”等，并给出数字（或以空格分隔的数字串），就原样抽取到对应的“卡号/尾号”字段。

- **不要求一定是 4 位**：可以是任意位数（例如尾号 62、尾号 12345、后 6 位 889900、完整卡号等）
- 如果用户只说“尾号 / 卡号”但没给出任何数字，则该字段置空
- 若用户给出完整卡号但未说“卡号 / 账号”等关键词，仅是孤立数字串且语义不明：不要强行当作卡号，置空
- 若用户仅指定了付款卡尾号（如：用我尾号 XXXX 的卡转），仅把抽取的尾号填入“付款卡卡号/尾号”字段，收款卡尾号置空
- 若用户仅指定了收款卡尾号（如：转给尾号 XXXX 的卡），仅把抽取的尾号填入“收款卡卡号/尾号”字段，付款卡尾号置空

#### 3. 收款卡银行识别

仅当【用户当前输入】明确出现银行名称/简称时填写。

允许模糊简称，例如：

- 农行 / 农行卡 / 农业银行
- 工行 / 工行卡 / 工商银行
- 建行 / 建行卡 / 建设银行
- 中信
- 招行 / 招行卡 / 招商银行

未提及则置空。

#### 4. 收款人姓名

- 若未明确收款人，输出空字符串
- 抽取用户明确说要转给谁的姓名（如“张三”“李四”“李明”等）
- 不要把银行名、家人 / 朋友 / 同事称呼、金额当姓名
- 不带姓氏的名字应该提取到收款人姓名字段中
- 若【用户当前输入】明确表达“转给本人 / 转给我自己 / 转给我 / 转到我账户 / 转回我卡 / 给自己转 / 转到自己名下 / 转到我的 XX 卡”等“收款人就是本人”的含义，则收款人姓名必须为【客户本人姓名】的值，且不得再把“我 / 自己 / 本人”原样输出为收款人姓名
- 当不能明确提取字段为收款人姓名还是收款卡备注时，可同时提取到收款人姓名和收款卡备注字段中

#### 5. 备注字段

备注信息涵盖：

- 家人朋友关系（如：儿子、妈妈、老婆、同事、女朋友）
- 银行卡类型（如：工资卡、理财卡等）
- 生活服务（如：房东、物业、家政、医疗、租房）
- 商业往来（如：客户、供应商、合作伙伴等）

**付款卡备注：**  
仅抽取用户对“付款卡 / 我这张卡 / 从哪张卡出”的称呼（如“工资卡、理财卡、日常卡”等）。

**收款卡备注：**  
提取除了银行名以外的要素（如“妈妈、儿子、老婆、同事、房东、女朋友、工资卡、理财卡”等），不应该提取具体银行的卡（例如建行卡、招行卡等）。

约束：

- 备注必须是【用户当前输入】出现的名词，**不得从姓名、关系或所属银行名称推断**
- 人称指代（如：你、她、他等）不是备注
- 当不能明确提取字段为收款人姓名还是收款卡备注时，可同时提取到收款人姓名和收款卡备注字段中

#### 6. 转账金额

- 输出 `number`（单位默认“元”）
- 支持从【用户当前输入】中提取转账金额
- 支持负数金额（如“-1000”“负500”）
- 支持阿拉伯数字与中文数字（如“一百二”“三千五”“两万”）
- 支持“万 / 万元 / 千 / 百 / 亿 / 兆”等换算，例如：
  - `1.5万 = 15000`
  - `80万 = 800000`
  - `2亿 = 200000000`
  - `1兆 = 1000000000000`
- 若金额区间 / 不确定（如“100 到 200”“随便转点”）则输出 `null`

#### 7. 手机号 / 尾号字段的定义

只要【用户当前输入】出现“手机号”等，并给出数字（或以空格分隔的数字串），就原样抽取到对应的“手机号/尾号”字段。

- **不要求一定是 4 位**：可以是任意位数（例如尾号 62、尾号 12345、后 6 位 889900、完整手机等）
- 如果用户只说“尾号 / 手机号”但没给出任何数字，则该字段置空

#### 8. 是否手机号转账字段

当用户提到“手机”“手机号转账”时，该字段为 `"true"`，否则置空字符串。

## 第三阶段：转账子工作流调用

模型只负责识别意图并填写 `payee_name`、`amount` 等槽位；不得在 prompt 中生成或调用工作流 URL、HTTP 请求或透传参数。

当必填槽位齐全时：

- 在 `router_only` 模式下，返回 `ready_for_dispatch`，不调用子工作流。
- 在 `execute` 模式下，仍返回 `ready_for_dispatch`；Router 会根据 machine-readable workflow reference 调用子工作流，并将子工作流 `node_output` 流式返回。

---

## 使用说明

1. 当用户输入需要分析时，首先执行**第一阶段**判断是否为转账意图
2. 如果第一阶段返回明确的转账意图，则继续执行**第二阶段**提取要素
3. 如果第二阶段提取成功，则交由 Router 在执行阶段调用子工作流
4. 如果第一阶段返回不支持的结果，直接将该结果返回给用户

## 执行约束（重要）

- **按顺序执行**：必须先完成第一阶段，再执行第二阶段；第三阶段由 Router 执行
- **一次性完成**：意图识别与提槽必须在一个对话轮次内完成，不要分多次调用
- **直接返回最终结果**：完成纠错后，直接将最终 JSON 结果返回给用户，不要再调用任何工具
- **禁止重复调用**：执行完成后立即停止，不要再次调用相同或相似的工具
- **用户输入信息完整性**：如果没有成功提取到收款人、转账金额信息，则必须提醒用户补全
